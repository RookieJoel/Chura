**ADR-004: WorkItem API structure**

| Title | WorkItem API structure |
| :---- | :---- |
| **Context** | Chura has a unique workflow for the work item where it shall have multiple creation stages. To make this work seamlessly without having much overhead on API calling, multiple API architectures have to be considered with the ultimate goal for the ease of use and continuity of the API calling. Options considered include plain REST API with direct access to the model’s repository, websocket based API, and gRPC with websocket API interface. The project would benefit from the option where it induces low effort when change is needed in the flow of the work item creation. |
| **Decision** |Use gRPC with websocket API interface. For the route which contains multiple steps such as the work item creation. gRPC is used as it allows stream processing which could be integrated with the work item creation flow via websocket interface.<br>For other CRUD operations within the domain model of the WorkItem, for the ease of development, it’s implemented as a discrete request and response via websocket interface. |
| **Status** | **Accepted** |
| **Consequences** | **Positive**<br> • This allows a multi-step and complex workflow of the work item creation to be finalized within one continuous network call. <br>• This approach reduces the connection overhead between backend server and frontend. <br>• This allows the frontend to perform a complex animation according to the creation stage from the backend. <br><br>**Negative**<br>• This may introduce the friction in frontend development if other domain’s model utilizes a different flow ( not a websocket interface ) <br>• This approach will need a reconnection handling logic in the frontend code <br>• This approach will need more configuration in the webserver to upgrade the http connection to support websocket interface. |
